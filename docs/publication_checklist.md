# Publication checklist

- Confirm the paper author's preferred name and citation metadata; a GitHub profile name is not assumed to identify the paper author.
- Choose and approve a software license; check terms for any redistributed third-party data.
- Upload preserved sources and verify their SHA-256 manifest.
- Recover exact generating code or explicitly identify reconstructed replacements.
- Address every blocking item in `reproduction_status.md`.
- Archive original catalogue selection, row count, epoch, field definitions, and checksums.
- Document ephemeris provenance, coordinate definitions, time scales, environment versions, and numerical tolerances.
- Generate and compare all tables and figures; retain comparison reports.
- Run independently validated astronomical checks over the historical interval.
- Review the complete scientific output before assigning a publication release.
- Create an immutable versioned archive and DOI through the chosen archive service; no DOI is currently assigned.
- Update manuscript repository URL, exact commit, release, and actual DOI. Do not leave placeholder identifiers.

Suggested interim data-availability wording, to use only after the source scripts have actually been uploaded:

"The supplied source scripts and a record of reproducibility limitations are available at https://github.com/jbghia/great-pyramid-solar-noon. The repository documents differences between the supplied implementations and the manuscript methods; complete numerical reproduction has not yet been established."

Use stronger wording only after the corresponding checks have actually been completed. Also revise the manuscript AI disclosure and independent-verification statements to match the work actually performed.
